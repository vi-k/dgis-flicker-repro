# Состояние работы

Обновлено 27.08.2026.

## Зачем это всё

Приложение воспроизводит дефект 2GIS Mobile SDK для передачи вендору. Исходная
задача — [TT-2359](https://teztaxi.atlassian.net/browse/TT-2359) в
tez-taxi-monorepo: у пользователей моргала и пропадала машина на карте во время
поездки. У себя закрыто обходом (частота записи угла срезана до 5/с), но это не
исправление — приложению естественно писать направление на каждом кадре
анимации.

## Что доказано

**Условие дефекта — частая запись `iconMapDirection` с изменившимся значением.**

Оба слова важны:

- запись того же значения движок пропускает, переукладки иконки не происходит,
  и симптома нет ни при какой частоте;
- порог по частоте лежит между 20 записями в секунду (за три минуты чисто) и 60
  (постоянные пропажи).

Во время пропажи карта, дороги, подписи и полилиния маршрута рисуются нормально
— отсутствует только маркер. Кадры-улики лежат вне репозитория, см. ниже.

Измерения и список проверенного-и-неважного — в `README.md`, текст для вендора —
в `docs/issue-2gis.md`.

## Чего НЕ доказано

- **`erasedPart` сама по себе полилинию не роняет.** На 60 записей в секунду за
  три минуты — ноль пропаж. Ранний вывод об обратном был ошибкой: он пришёл из
  прогона, где вдобавок работало пересоздание маршрута.
- **Пропажа обоих объектов разом** наблюдалась только когда обе записи идут на
  60/с. При записи одного лишь направления линия остаётся целой.
- **Редкие кадры с пустой картой целиком** (пропадают и тайлы, и подписи)
  встречались несколько раз, примерно раз в девять минут. Отдельное явление,
  не разобрано, в обращение не вошло.
- **SDK 14.0.0 не проверен.** Ветка `sdk-14` собрана и готова, прогона не было.

## Грабли инструментов

Обе стоили по несколько часов и обе давали правдоподобный, но ложный результат.

- **`ffmpeg -ss` до `-i`** — быстрый поиск по ключевым кадрам: отдаёт не тот
  кадр, а иногда мусорный, декодированный без опорных. Проверять кадры только
  по точному номеру: `-vf "select=eq(n\,N)" -fps_mode passthrough`.
- **`screenrecord` пишет с переменной частотой.** Без `-fps_mode passthrough`
  ffmpeg приводит её к средней, выбрасывая кадры: номера расходятся с файлом, а
  короткий эпизод теряется целиком. В `tools/darkcount.py` это учтено.
- Правило, выведенное дорогой ценой: **любой найденный провал проверять
  кадром**, прежде чем делать вывод. Из проверенных так провалов больше половины
  оказались артефактами — то камера уводила объект за край, то трасса
  заворачивалась, то объект уходил под шторку.

| Vivo V2310, Android 14 (устройство QA) | `kz.nidge.tez_taxi.tez_taxi.stage` | stage | стоит репро; stage-клиент снесён, рядом стоит dev-клиент |

Оба на 27.08 ушли с сети — подключать заново, проще кабелем.

Ключ 2GIS проверяет идентификатор приложения, поэтому репро собирается под
занятый app id:

```bash
REPRO_APP_ID=kz.nidge.tez_taxi.tez_taxi.dev \
  flutter build apk --release --target-platform android-arm64
```

Ключ кладётся в `assets/dgissdk.key` (в репозиторий не входит), берётся из
`apps/client/assets/gis_keys/<flavor>/dgissdk.key` монорепо.

## Что осталось

1. Прогнать ветку `sdk-14` на устройстве: собирается, нужен только стенд. Если
   на 14.0.0 не воспроизводится — задача меняется целиком, обращение не нужно,
   нужен апгрейд SDK.
2. Отправить `docs/issue-2gis.md` в 2GIS. Публичного трекера у Flutter SDK нет,
   канал — личный кабинет или почта.
3. По желанию — добить редкие кадры с пустой картой целиком.

## Улики

Кадры и записи прогонов лежат в `evidence/` рядом с проектом и в репозиторий не
входят (гигабайты видео). Ключевые пары «до/после»: пропажа маркера при
`iconMapDirection` 60/с и пустая карта целиком.
