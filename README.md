# Маркер пропадает на несколько кадров при записи `iconMapDirection`

Минимальное приложение на 2GIS Mobile SDK для Flutter, воспроизводящее дефект
отрисовки: во время движения маркер машины исчезает на два-пять кадров и
появляется снова. Линия маршрута в это время продолжает съедаться, камера
продолжает двигаться — то есть кадры рисуются, а маркера в них нет.

Кроме `dgis_mobile_sdk_full` в проекте нет ни одной зависимости: ни своих
обёрток над картой, ни сетевого слоя, ни бэкенда. Всё, что делает приложение, —
пишет в объекты SDK то же, что писало бы приложение такси.

## Симптом

Ведомая машина едет по маршруту. Раз в 5.4 с приходит «новая точка», между
точками позиция и курс интерполируются на 20 тиках в секунду в течение двух
секунд, дальше машина стоит до следующей точки. На каждом тике в маркер
пишутся `position` и `iconMapDirection`.

Эпизодически маркер пропадает из кадра на 2–5 кадров подряд, потом появляется
на 1–3, и так примерно полторы секунды. Дальше едет ровно.

## Что мы уже установили

- **Дело в записи `iconMapDirection`, а не `position`.** На прогоне с
  выключенной записью направления машина не моргнула ни разу за четыре с
  половиной минуты; включили обратно — моргнула сразу. Запись позиции при этом
  шла всё время, на каждом тике.
- **Маркер не пересоздаётся.** За сессию один `addObject` и ноль
  `removeObject`.
- **Значения исправные.** Ни одного нечислового значения ни в координатах, ни в
  углах; таймер анимации не голодал — 40 тиков из 40 ожидаемых, факт против
  плана 2000–2008 мс.
- **Пересоздание полилинии ни при чём.** Прогоны, где полилиния снималась и
  добавлялась заново каждые 20 секунд, шли чисто; а в сессии, где симптом был,
  маршрута не было вовсе.
- **`animatedAppearance: false` делает эффект заметным.** С дефолтным `true`
  переукладка иконки выглядит как полупрозрачность, с `false` — как полная
  пропажа. Флаг стоит `false`, потому что ведомая машина живёт всю поездку и
  «появляться» ей незачем.
- **Зависит от железа.** На Samsung A55 (1080×2340) шесть прогонов подряд были
  чисты, на Vivo V2310 (Android 14) симптом воспроизводится. Прогон с
  подогнанной геометрией экрана (`wm size 720x1600`, `wm density 300`) на A55
  тоже был чист — значит дело не в размере растра иконки, а в GPU и драйвере.

Из этого мы делаем вывод, что запись `iconMapDirection` заставляет движок
переложить иконку, и на слабом GPU эта переукладка занимает кадры.

## Запуск

Ключ SDK в репозиторий не закоммичен. Положите свой:

```bash
cp assets/dgissdk.key.example assets/dgissdk.key
# и впишите в него свой ключ
```

Стиль карты приложения (`assets/map_style.2gis`) в репозиторий не входит: без
него берётся стиль SDK. Со стилем карта тяжелее — больше слоёв и подписей.

Ключ читается по умолчанию — из `assets/dgissdk.key`, как в примере из
поставки SDK; путь резолвится относительно `assets/`.

Ключ 2GIS привязан к идентификатору приложения. Здесь он
`kz.teztaxi.dgis_flicker_repro`; если ваш ключ выдан на другой — соберите с
переменной окружения:

```bash
REPRO_APP_ID=<ваш идентификатор> flutter build apk --release
```

```bash
flutter pub get
flutter run --release
```

Собранный APK содержит ключ в ассетах, поэтому передаётся исходник, а не
готовая сборка.

Проверялось на Flutter 3.44.4 / Dart 3.12.2, AGP 8.11.1, Kotlin 2.2.20,
Gradle 8.14.3 — тот же тулчейн, что у приложения, где снят симптом.

Версия SDK закреплена в `pubspec.yaml` — `13.7.0`, та, на которой снят симптом.
Для проверки на актуальной поменяйте её на `14.0.0`: там
`MapWidgetController` требует `sdk.Context` первым позиционным параметром,
остальной код меняться не должен.

## Как воспроизвести

Стенд — слабое Android-устройство. На флагманах симптом может не проявиться.

1. Запустить, дождаться карты. Дефолт уже боевой: `iconMapDirection`
   пишется каждый тик, `animatedAppearance` выключен, маршрут рисуется,
   съедается и пересоздаётся раз в 20 с.
2. Смотреть на машину полминуты-минуту. Ожидаемое поведение — маркер виден
   всё время. Фактическое на слабом устройстве — периодически пропадает.
3. Перевести `iconMapDirection` в `выкл`. Позиция продолжает писаться каждый
   тик, машина продолжает ехать. Моргание прекращается.
4. Вернуть `каждый тик` — моргание возвращается.

Каждый тумблер меняет ровно одну переменную, так что операцию можно выделить
включением по одной:

| Ручка | Что меняет |
|---|---|
| `iconMapDirection` | частота записи направления: каждый тик, 10/с, 5/с, выкл |
| Трасса | «из тикета» — длинные прямые, курс почти не меняется; «змейка» — курс ходит ±45° |
| Маркеров | 1, 5 или 20 вращаемых маркеров: во столько же раз больше записей |
| Тик анимации | 20, 30 или 60 Гц |
| Ширина иконки | 63, 96 или 128 логических пикселей |
| Графика | `GraphicsPreset.lite` (боевой) или `normal` |
| `animatedAppearance` | опция создания маркера; переключение пересоздаёт маркеры |
| Линия маршрута | добавлять полилинию или нет |
| Съедание `erasedPart` | писать долю съеденного (не чаще 10 раз в секунду) |
| Маркер и линия в одном `MapObjectManager` | держать их вместе — состояние до того, как маркер вынесли в собственный менеджер |
| Мигающий маршрут | снимать и добавлять полилинию раз в секунду: тот же объект, без новой геометрии |
| Пересоздание линии | снимать и добавлять полилинию заново раз в 20 с |
| Камера следует за машиной | один линейный перелёт камеры на событие; включена по умолчанию, иначе машина уходит за край экрана |

Кнопка глаза в правом верхнем углу убирает HUD и панель — для чистой записи
экрана.

## Как измерить

Глазами моргание ловится плохо, поэтому кадры считаются.

**HUD сверху** показывает частоту кадров и время растра за последние 10 секунд,
а рядом — сколько записей ушло в SDK за последнюю секунду. Ровный `кадры 60/с`
в момент, когда машины нет на записи, и есть главное наблюдение: кадр
отрисован, маркера в нём нет.

**`tools/darkcount.py`** считает тёмные пиксели по кадрам записи экрана. Машина
— единственный крупный тёмный объект на светлой карте, и число тёмных пикселей
не зависит от того, куда она сдвинулась; пропала — счётчик проваливается.

```bash
adb shell screenrecord --time-limit 60 /sdcard/repro.mp4
adb pull /sdcard/repro.mp4
python3 tools/darkcount.py repro.mp4 --quiet
```

Нужен только ffmpeg в PATH. Скрипт печатает медиану и список провалов с
таймкодами. По умолчанию он отрезает верх и низ кадра, где стоят HUD и панель;
если записывали с убранным интерфейсом, снимите обрезку: `--top 0 --bottom 1`.

## Чего репро пока не даёт

Честно о границах: на двух слабых устройствах (Vivo V2310, Android 14, Mali-G57
и Redmi Note 10 5G, Dimensity 700) пропажу маркера воспроизвести **не удалось** —
ни на боевых параметрах, ни при нагрузке в шестьдесят раз выше, ни со снятыми
обходами. Проверены: запись угла каждый тик, до 1240 записей в секунду, общий
`MapObjectManager`, мигание полилинии, стиль приложения, пресеты `lite` и
`normal`, иконки до 128 lp, до 20 вращаемых маркеров.

Симптом наблюдался у QA на живом заказе, и там же разделялся тумблером
вращения: с записью направления машина моргала, без неё — за четыре с половиной
минуты ни разу. Это приложение — стенд, чтобы ту же гипотезу можно было крутить
на своей стороне, а не доказательство само по себе.

## Из чего состоит

| Файл | Что делает |
|---|---|
| `lib/main.dart` | инициализация SDK, карта, экран |
| `lib/repro_scene.dart` | объекты карты и таймеры: кто, что и когда пишет |
| `lib/repro_settings.dart` | ручки прогона |
| `lib/controls_panel.dart` | панель тумблеров |
| `lib/frame_hud.dart` | кадры и счётчики записей |
| `lib/route_data.dart` | трасса: боевая и змейка |
| `lib/car_icon.dart` | иконка рисуется в рантайме, бинарных ассетов в репозитории нет |
| `lib/geo.dart` | геометрия: расстояния, курс, точка на ломаной |
| `tools/darkcount.py` | подсчёт тёмных пикселей по записи экрана |

Вся работа с SDK — в `lib/repro_scene.dart`, около трёхсот строк.
